OpenCard ships embeddable JS plugins for partner sites.

These are **optional UI helpers**. For the full API path (billing → TPA → organization → webhook → card holders), start with [Customer onboarding](/ems/customer-onboarding) — you can integrate without these plugins.

---

## ocTPA — TPA onboarding wizard

Self-service wizard that mirrors [customer onboarding steps 1–4](/ems/customer-onboarding#step-by-step):

1. Pick payment product (`GET .../payment-products` on the account)
2. Pick add-ons (transactions + optional enrichment)
3. Invoice email / reference
4. Signatory combination + emails (`GET .../publicrecords`)
5. Hand payload to you via `onDataSend`

**Load:**
```html
<script src="https://api.opencard.io/plugin/tpa/js/tpa.min.js"></script>
<link rel="stylesheet" href="https://api.opencard.io/plugin/tpa/css/tpa.min.css">
```

**Init:**
```javascript
new ocTPA({
  environment: 'sandbox', // or 'production'
  oAuthToken: 'Bearer ...', // scopes: public-records-read + account-payment-products-read only
  accountId: 1,
  orgNumber: '5561234567',
  country: 'SE',
  allowedPaymentProductIds: [], // optional: payment product `id`s to show (default: all enabled on the account)
  infoAndPriceMapping: { 1: 'https://your-site/pricing/product-1' }, // optional: "Info & Pricing" URL per payment product id
  onDataSend: async function(data) {
    // YOU call the APIs — plugin does not write to OpenCard:
    // 1. POST /billings (data.billing) — includes product_* flags
    // 2. POST /tpas (data.tpa)
    // 3. POST /tpas/{id}/signatories for each in data.tpa_signatories
    // 4. POST /organizations (tpa_id + billing_id from steps 1–2)
    // 5. POST /organizations/{id}/webhooks — REQUIRED before any card holder
    // Then: card holders
    return true; // or error string
  }
});
```

<Warning>
**The plugin stops at the TPA.** It never creates the organization or the webhook — there is nothing in the `onDataSend` payload for them, because the webhook URL is *your* endpoint, not client input. You must create both in your `onDataSend` handler (or immediately after) using the ids returned from the billing and TPA calls. A client with a TPA but no webhook will fail at PDPC signing. See [The order matters](/ems/customer-onboarding#the-order-matters).
</Warning>

```json
{
  "billing": {
    "name_display": "...",
    "name_legal": "...",
    "organization_number": "...",
    "country": "SE",
    "address_street": "...",
    "address_city": "...",
    "address_zip": "...",
    "email_invoice": "...",
    "your_reference_invoice": "...",
    "product_transaction": true,
    "product_digital_receipt": true,
    "product_aland_index": false
  },
  "tpa": {
    "language": "sv",
    "name": "...",
    "country": "SE",
    "organization_number": "...",
    "payment_product_id": 1
  },
  "tpa_signatories": [
    { "name": "Anna", "email": "anna@acme.se" }
  ]
}
```

## ocPDPC — consent link helper

Lightweight modal that opens the PDPC signing URL in a new tab.

```javascript
new ocPdpc({
  pdpcUrl: 'https://api.opencard.io/accounts/1/pdpcs/3/sign/token...',
  message: 'Please approve data processing for your corporate card.',
  buttonText: 'Approve now'
});
```

Display-only. No API calls.
